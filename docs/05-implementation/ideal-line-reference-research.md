# Синтетический эталон «быстрее твоего PB»: финальный отчёт

## 1. Короткий вывод и рекомендация

Строить синтетический оптимальный круг **можно и нужно целиком в офлайн-бейке** из уже имеющихся данных (медианный centerline из ADR-0014 + оценённый по своим кругам коридор + оценённый по своим кругам grip), а на выходе класть его в форме `ResampledLap`. Это единственный путь, совместимый с ограничениями проекта (sim-agnostic, нет живого быстрого пилота, нет чистой публичной телеметрии).

Однако после проверки исходной рекомендации её приоритеты **разворачиваются**:

- **Рекомендуется как основной поставляемый результат — Этап 1 (перепрофилирование скорости на фиксированном centerline), а не двухшаговый QP-оптимизатор трассы.** Двухшаговый QP из черновика был помечен как «RECOMMENDED headline», но у него на наших данных **почти нулевой запас**: коридор построен по разбросу линий одного и того же пилота (в поворотах часто < 0.5 м), поэтому оптимизатор траектории почти воспроизведёт медианную линию самого пилота при полной стоимости солвера/лицензий/Python.
- **Честно о «быстрее твоего PB».** Главная угроза цели — **самореферентный потолок**. И коридор, и grip оцениваются по кругам того же пилота. Любители систематически **недозаполняют круг трения**, особенно в торможении и на входе с торможением (trail-brake) — ровно там, где кроется самая большая потеря времени. Перцентиль+выпуклая оболочка такого облака **занижает** тормозной и комбинированный grip. Поэтому «сырой» эталон структурно упирается в потолок *«твой собственный лучший-когда-либо grip, применённый везде»* — это выигрыш в **консистентности**, а не «алиен»-темп. Формулировка черновика «человеческие пики — безопасная нижняя граница → эталон достижим» **перевёрнута наоборот** для заявленной цели.
- **`grip-scale > 1` — это магическое число без физической основы** и прямое нарушение правила репозитория «все пороги из конфига, без магических чисел». Слишком большой — фантазия; слишком маленький — нет выигрыша; данных, чтобы выбрать его честно, нет (истинный grip шины никогда не наблюдался). Его нужно заменить **физически ограниченным** восстановлением «пустых» квадрантов g-g и калибровкой против `v = sqrt(mu·g·R)`.
- **«Никакого нового рантайма, просто падает в compare» — неверно** для синтетического TIME-эталона. Подтверждено в коде: `ReferenceStore.MaybeUpdate` перезаписывает единственный `_reference` на любом более быстром чистом круге (ADR-0017), а `ComputeSession` держит ровно один эталон. Синтетику либо затрёт первый же чистый круг, либо она захватит семантику PB. Нужен **отдельный слот** (по образцу вендоренного per-track centerline / M38 LINE), проброшенный через пути дельт вручную — это реальная рантайм-работа, а не ноль.

Итог: **отгружаем Этап 1 как «эталон идеальной скорости + консистентности» с честной подписью (не «алиен»), а Этап 2 (QP-траектория) переводим в статус явно-гейтированного эксперимента**, который строится только если дешёвый spike покажет измеримый выигрыш линии над Этапом 1.

## 3. Рекомендованный пайплайн для НАС

Всё считается офлайн в `tools/SimCoach.Bake`; в рантайм уходит только артефакт `ResampledLap`.

### Что считаем (from centerline + estimated width + estimated grip → synthetic ResampledLap)

**Блок A — оценка grip (g-g-v), но с восстановлением «пустых» квадрантов.**
1. Берём (GLong, GLat) по кадрам. **Единицы — g, конвертировать в м/с² (×9.81)** до физики, иначе апекс-скорости в ~3× неверны (подтверждено: `GForceG = physics.AccG`, поле 23).
2. **Не** переиспользовать `CenterlineBin.LateralG` — это медиана |боковой g|, а не граница трения; нужно совместное распределение (lat=AccG.X, long=AccG.Z), биннинг по скорости (downforce).
3. **Не** дифференцировать WorldPos для g (занижение пиков ~2×).
4. **Ключевое против самореферентности:** любители достигают почти пикового *бокового* grip на апексе, но недозаполняют торможение/комбинированную зону. Поэтому: подгоняем симметричный эллипс трения к хорошо населённому *боковому* пику и **зеркалим/экстраполируем grip торможения и комбинированной нагрузки** из физики эллипса, а не из робкого облака данных. По возможности **пулим пики по всем сессиям (best-ever, кто бы ни выжал)**, чтобы поднять огибающую к истинному пределу.
5. Вместо `grip-scale > 1` — **физически ограниченный derate/inflate, провалидированный против `v = sqrt(mu·g·R)` по радиусам поворотов**, как калиброванный конфиг-параметр с задокументированной границей.

**Блок B — коридор.** Знаковый боковой офсет кадров от centerline, робастные перцентили по бинам. **НЕ вычитать полуширину машины** из наблюдённого envelope: envelope точки-референса машины (`graphics.CarCoordinates`) уже есть нижняя граница проезжаемого; вычитание из ленты, которая сама может быть < 0.9 м, инвертирует границы и делает QP-box вырожденным/несовместным. Максимум — маленький фиксированный инсет в конфиге.

**Блок C — скорость (v1, основной результат).** Сглаживающий **периодический** сплайн по centerline → κ(s). **Не** дифференцировать сырые бины: `LapSamples=0` (carry-fill, копия предыдущего) даёт нулевое смещение → κ=0/NaN и `v=sqrt(a_y/κ)` взрывается (подтверждено в `MedianCenterlineBuilder`). Интерполировать сквозь `LapSamples=0` и восстановить ведущий gap, чтобы петля замкнулась. Forward-backward проход по эллипсу трения → интеграл ds/v в время.

**Фильтрация входов (оба блока).** Отбрасывать кадры `IsInPitLane/IsInPit` (поля 41/42) — сейчас гейт только по-круговой (`IsValidLap`), а out-lap/пит-транзит отравляет и коридор (большой боковой выброс), и g-g-v (искусственно низкий grip). `TyresOut` на ACC всегда 0 — off-track по кадру недоступен, опираемся на per-lap гейт + робастные перцентили.

**Сегментация ключа.** Бейк пулит по `trackId` **только** (подтверждено). Grip сильно зависит от машины и погоды → строить g-g-v как новую редукцию по ключу **(track, car, weather)** с порогом минимума кругов (по образцу `MinLapsForTrust`); геометрия per-track + grip per-(car,weather) = синтетика per-(track,car,weather). Не эмитить эталон при выборке ниже порога.

**Регистрация эталона (реальная работа, не ноль).** Отдельный слот, грузится как вендоренный per-track датасет (паттерн `CenterlineGeometryDataset` / M38 LINE), **не** через `ReferenceStore`; исключить из `MaybeUpdate`; определить приоритет против PB TIME (ADR-0019) и M38 LINE. Заполнить `SpeedMps` + `TMsFromLapStart` (сейчас нули).

### Честная оценка качества

- Это **НЕ «алиен»-круг.** Это эталон *«идеальная дисциплина скорости + физически-заполненный тормозной grip + оптимальное связывание поворотов газ/тормоз»* — то, что человек не делает консистентно. Позиционировать в коуч-копирайте именно так, без over-promise.
- **Point-mass + QSS оптимистичны недостижимым образом:** идеализированный круг трения структурно на ~5–10% быстрее реального (игнор переноса нагрузки, load-sensitivity шины, аэро-yaw). Ошибка **не корректируется в модели и не «достижима»**: при переносе нагрузки μ падает → чистая потеря комбинированного grip против равномерно нагруженного эллипса. Поэтому нужен **явный achievability-derate на итоговое время** (или тюнинг показателя эллипса p), иначе дельта навсегда отрицательна и эталон читается как фантазия. Нюанс: QSS-vs-transient исследования показывают, что **линия почти не меняется** — геометрия защитима, ревизии требует абсолютное **время**.
- Подавать эталон как **по-поворотные/по-секторные под-цели**, а не один недостижимый круг — так коуч-сигнал остаётся калиброванным и мотивирующим.

### Главный риск и как его обойти

> **«Оценка grip по своим кругам может воспроизвести твой же потолок».** Двойная самореферентная ловушка: и коридор (used-envelope), и grip (человеческие пики) ограничены тем же пилотом. Синтетика структурно заперта внутри уже показанного человеком по **обеим** осям — геометрии и grip.

Обход:
1. **Восстановить пустые квадранты g-g из физики** (эллипс от бокового пика → зеркало на торможение/комбинацию), а не брать сырой тормозной пик.
2. **Пулить пики по сессиям/пилотам** (best-ever), поднимая огибающую к истинному пределу.
3. **Заменить `grip-scale` на калиброванный derate**, провалидированный против `v=sqrt(μgR)`.
4. **Расширить коридор к настоящим краям**: детектить off-track/kerb-кадры и строить occupancy-grid по ВСЕМ кругам (включая офф-траки и разные линии) или брать края из track-model; валидировать восстановление ширины на TUM `racetrack-database`, где ширины известны.
5. **Санити-баунд**: ограничивать синтетическое время реальными быстрыми community/PB-кругами и независимым QSS-симулятором времени круга, чтобы не уплыть в фантазию.

## 5. Поэтапный план внедрения

### Spike (гейт, ~0.5–1 день) — до любого кода солвера
- Испечь реальный коридор на 1 трассе, прогнать `opt_min_curv` (или K1999), **измерить фактический боковой сдвиг линии и дельту времени круга vs Этап-1** на реальных запечённых данных.
- Санити: подтвердить семантику/знак/единицы GLat/GLong и сколько чистых кругов нужно, пока g-g-v не перестаёт «плыть».
- **Решение:** строить Этап 2 только если сдвиг/дельта превышают заранее заданный порог. При used-envelope коридоре запас, вероятно, мал.

### v1 (~2–4 дня + блоки) — ОСНОВНОЙ РЕЗУЛЬТАТ: скорость на фиксированном centerline

## 1. Вердикт: NO-GO на число, GO-WITH-CAVEATS на метод

**Итоговое вычисленное число: derated 109.586 s (raw QSS 106.394 s), +3.414 s к PB 113.000 s.**

Это число **не доказывает** доверительную «цель за пределами PB». Оно ложится внутрь заранее выбранного «credible» окна [106 s, 113 s] — но только потому, что (а) само окно привязано неверно, и (б) две крупные противоположные ошибки взаимно гасятся. Прирост +3.4 s держится на **двух непроверенных свободных параметрах** — уровне сцепления `a0` и коэффициенте derate `eps` — и любое равнозащитимое их смещение обнуляет прирост:

| Сдвиг | Значение | Итог | Прирост к водителю |
|---|---|---|---|
| `a0` = 1.49 g (заявленное) | flat fit | 109.5 s | +3.4 s |
| `a0` = 1.40 g (**собственный измеренный p95 водителя**) | measured | 111.2 s | +2.2 s |
| `a0` = 1.30 g (slick-floor; и то, что даёт нeзажатый FFT-fit) | prior floor | **113.3 s ≈ водитель** | **~0 (нет прироста)** |
| derate `eps` = 8% (наивный) | | **114.3 s** | **−0.9 s (медленнее водителя)** |

«Робастный коридор 109.0–109.6 s» варьировал **только сглаживатель кривизны**, удерживая `a0 ≈ 1.49 g` в обеих ветках — то есть измерял шум сглаживателя, а не доминирующую неопределённость. Честная полоса неопределённости — **от «нет прироста» до +3.4 s**. Флаг `trustworthy: true` из вычислительного прогона **не подтверждается**.

**Что решается:**
- **NO-GO** — не публиковать 109.6 s как «доверительный оптимум/цель». Это не оптимум машины, а число «улучшение середняка», одетое в слова «optimal».
- **GO-WITH-CAVEATS** — сама конструкция (speed-dependent g-g-V envelope + friction-ellipse QSS) — верное направление, **не** фантазия (не взорвалась в sub-100 s) и **не** коллапс в PB по построению. Продолжать разработку метода можно **только** после обязательных фиксов из §3–4.

## 2. Ломает ли «mu из лучшего угла» самореференцию — НЕТ, на этих данных гипотеза фальсифицирована

Ключевая гипотеза («водитель на пределе хотя бы в одном углу раскрывает mu, и это mu держит всюду») **на реальных данных Monza не подтвердилась**. Четыре независимо проверенных причины:

1. **«Лучший угол» — не на пределе.** Газ в апексе top-mu углов: s=5210 (1.92 g) → **34%**; s=5319 (1.77 g) → **98%**; s=4067 → 92%; s=4152 → 87%. Угол, взятый на 87–98% газа в апексе, ограничен тягой/выходом, а не боковым сцеплением — его `v²·κ` не говорит о capability.
2. **`v²·κ` с центрлайна — не «over-read», а шум** относительно измеренного канала: где-то +0.26/+0.56 g завышает (s=5210, s=5319), где-то −0.40 g занижает (s=4152). «Max per-corner mu» выбирает **не самый закоммиченный угол водителя, а станцию с худшим рассогласованием центрлайн-vs-racing-line.**
3. **Аэро-член неидентифицируем.** Биннинг *использованного* `a_lat` (`v²·κ`) восстанавливает «как сильно водитель решил давить», а не `a_lat_max` шины. Робкий near-PB водитель недожимает быстрые углы → огибающая немонотонна → fit даёт **отрицательный** аэро-наклон `a1`, который guard зануляет. Метод схлопнулся в **единый ПЛОСКИЙ mu = 1.49 g** — ровно тот constant-mu, который Option A должен был заменить.
4. **Этот плоский mu превышает собственный измеренный p95 водителя на +6.7%** (1.49 g vs проверенные 1.396 g; облако `v²·κ` даёт max 2.09 g против физического потолка круга 1.944 g). Значит модель **не «раскрывает скрытый предел», а завышает геометрию.**

**Вывод:** двойная самореференция не была чисто разорвана — она заменена на **ловушку геометрического over-read**. Видимый прирост складывается из этого завышенного сцепления + оптимистичной плоской оси торможения 2.2 g, **частично** скомпенсированных тем, что модель **недоезжает быстрые углы относительно самого водителя** (Parabolica: модель 216 vs водитель 222 км/ч; R=98 м: 136 vs 149; R=73 м: 118 vs 133). Настоящий point-mass оптимум обязан быть ≥ человека **в каждом** углу — здесь он медленнее там, где GT3 делает время.

## 4. Конкретный метод к реализации (если GO) — Option A + обязательные фиксы

Скелет остаётся (offline bake, sim-agnostic, geometry+telemetry): Step 0 сегментация → Step 1 кривизна из геометрии → Step 2 огибающая `a_lat_max(v)=a0+a1·v²` → Step 4 friction-ellipse → Step 6 forward-backward QSS → Step 7 derate → Step 8 sanity-gate. Что **обязательно** добавить/переделать:

1. **Калибровка по измеренному `LateralG` (снимает самореференцию честно).** Строить огибающую по измеренному каналу g; `v²·κ` использовать только для геометрии/апексов после per-station сверки. Hard-reject любой огибающей с `a_lat_max(v) > measured_p95 · (1 + LateralGCalibTolerance)`.
2. **Реализовать grip-limited gate** перед биннингом (условие: `|v−v_localmin| < ApexProximityWindowM` И `throttle < ThrottleGateMax` И не тормозит жёстко).
3. **Раздельный фит `a0` и `a1`.** `a0` — только по `v < LowSpeedGripCutoffKmh` (аэро≈0). Если `a1` неидентифицируем — **зажимать** быстрые углы величиной `a0`, никогда не поднимать тихоходные.
4. **Скоростно-бинированная ось торможения** `a_x_brake_max(v)` вместо плоского скаляра; reject >~2.2 g как шум дифференцирования; тяжёлое сглаживание v перед `dv/dt`.
5. **Per-corner lower-bound ассерт**: apex модели ≥ committed apex водителя во всех углах, иначе поднять огибающую.
6. **Racing-line радиус**, а не сырая медиана центрлайна (min-curvature линия или физический пол min R), с совместным пересчётом committed-mu и apex-cap.
7. **Derate — вывести, не угадывать**: измерить QSS-vs-actual gap на прямых/известно-предельном угле самого водителя; публиковать raw QSS как явную границу.
8. **Переякорить sanity-gate** к реалу: pole ~104.5–105.1 s, alien-floor ~106 s; внешний cross-check (OpenLAP/OptimumLap на той же GGV) вместо самореферентного окна.

## 6. Перепроверка на ИЗМЕРЕННОМ g (2-я фальсификация) → NO-GO

   фиксированный **point-mass QSS / median-line оптимизм геометрии**, самопорождённый, а не grip-driven.
2. **Единственный не-циркулярный член** (`extra_from_global` — грип, импортированный из ДРУГИХ поворотов)

   неразрешимы. 7 кругов не позволяют сузить пол до сигнала ~1–6 km/h.
3. **Посылка «водитель недоиспользует грип здесь» ИНВЕРТИРУЕТСЯ в 4/8.** На C4/C5/C7 собственный
   tight-apex p95 g водителя (1.948/2.005/2.548g) уже ≥ глобальной p98-огибающей (1.696g). «Больше
   скорости» там — это crash-tip, а не grip-budget-tip.

**Почему §4-фиксы не спасают:** контаминация транзиентами НЕ снимается флагом `tyres_out` (raw abs-max
3.155g/−7.17g переживают фильтр; события >1.9g длятся ≤130 ms, медиана 3 кадра ~9 ms — это поребрики/
вертикаль, не sustained-грип). Очистка до физичного p95=1.532g лишь **уменьшает** огибающую и толкает
grip-import ещё более в минус. Median-line over-read — улучшился (implied-g residual −0.07g, старый режим
провала почти исправлен хорошей медианной линией), но его сменил новый доминирующий режим: **равномерный
point-mass QSS-оптимизм ~26 km/h**, который и есть вся «дельта».

**Итог:** 0 поворотов дают дельту, одновременно не-циркулярную, выше шума и line-safe. Измеренный g **не
разорвал** самореференцию — он её переместил. Это **2-я фальсификация** Option A (наивная, затем на
измеренном g). Вывод судьи: **абсолютный beyond-PB apex-speed таргет из собственных данных водителя
недостижим by construction** — нужен ВНЕШНИЙ якорь.

**Рекомендованный путь вперёд (эскалирован владельцу, не решён):**
- **Отбросить** driver-median measured-g огибающую как источник абсолютных apex-speed-таргетов.
- **Пивот на внешний якорь:** track-boundary-constrained оптимальная racing line (вендорить per
  car/track, в русле существующего bake в `tools/SimCoach.Bake` + `SimCoach.Reference`), чтобы «больше
  скорости» отделялось от «другая линия», а таргет валидировался против выполнимой линии и капился
  demonstrated-best apex водителя. **Реплей-захват (`AllowReplayCapture`) уже включён** — это и есть
  канал для внешнего эталонного круга (option B).
- **Параллельно — безопасный сигнал, который измеренный g ВСЁ ЖЕ даёт:** ОТНОСИТЕЛЬНый коучинг
  (дельты точки отпускания тормоза / тайминга газа vs личный PB), НЕ абсолютные числа apex-speed.
- Абсолютный speed-таргет пересматривать только после: (a) load-transfer/aero/combined-slip QSS-модели
  с residual≈0 на предельных углах (схлопывает ~26 km/h bias); (b) sustained-window gate ≥0.3 s +
  vertical-g канал против транзиентов; (c) мульти-сессионных данных чтобы grip-import вышел из шума.

## 7. Option B → MoTeC `.ld` импорт (внешний круг из файла) — LINE невозможен, шиппабельного alien нет

После того как SHM-реплей оказался мёртв (`acc-shared-memory-layout.md`: реплей обнуляет физику/замораживает
координаты), рассмотрели внешний эталон из **файлового** экспорта ACC MoTeC (`.ld`/`.ldx`). Три параллельных
ресёрч-агента (формат `.ld`; тоггл ACC + список каналов; доступность alien-`.ld`) + локальный воркспейс.

**Под-теории:**

| | Утверждение | Вердикт |
|---|---|---|
| **T1 — парсинг** | Можем распарсить ACC `.ld` и достать каналы | **ВЕРНО** (feasible) |
| **T2b — LINE-эталон** | Из `.ld` строится линия, привязанная к нашей мировой сетке | **ФАЛЬСИФИЦИРОВАН** |
| **T2a — шиппабельный beyond-PB источник** | Есть распространяемый чужой быстрый `.ld` | **ФАЛЬСИФИЦИРОВАН** |

**T1 (верно):** формат документирован — little-endian, magic `0x40`, каналы = связный список contiguous-блоков
(`datatype_a`+`datatype`, `scale/mul/shift`), `.ldx` = XML лап-маркеры (Time в микросекундах). Опоры для
порта: `gotzl/ldparser` (GPL — только спека, не копировать код), `t-babin/ACC-Telemetry-Tracker` (C# MIT).
Каналы ACC пишет богатые: `Ground Speed`, `Throttle Pos`, `Brake Pos`, `Steering Angle`, `Gear`, `Engine RPM`,
`CG Accel Lateral/Longitudinal` (gLat/gLon), wheel speeds, susp, tyres. Тоггл (по умолчанию 0, оттого нет
файлов): в игре — сетап машины → **ELECTRONICS → TELEMETRY LAPS → N**; экспорт последних N кругов per-session
в `Documents/.../MoTeC/`, без фильтрации невалидных.

**T2b (фальсифицирован — ключевой факт):** в `.ld` **НЕТ** мировых XYZ, **НЕТ** канала дистанции, **НЕТ**
spline/normalized позиции. MoTeC i2 рисует трассу **dead reckoning**: дистанция `s=Σ(v·dt)`, курс
`θ=Σ(a_lat/v·dt)`, точки `x=Σ v·cosθ·dt`, `y=Σ v·sinθ·dt`, затем loop-closure коррекция размазывает
накопленную невязку. Результат — **форма в произвольной, дрейфующей, метрически неточной локальной рамке**, не
мировые координаты. Наш движок читает ИСТИННЫЕ `carCoordinates` из SHM → чужую dead-reckoned линию к нашему
центрлайну можно лишь **registration**-нуть (2D rigid+scale к известной геометрии трассы) со свойственной
дрейфу ошибкой — недостоверно для «сдвинь линию на 0.5 м». Свой `.ld` для линии бессмыслен (SHM точнее).

**T2a (фальсифицирован):** курируемого публичного корпуса alien-`.ld` нет. Годные — платные, лицензия
personal-use (Coach Dave Delta, Driver61 Hotlaps.io/trophi.ai), бандлить в продукт нельзя. Free-шеринг ad-hoc,
без provenance. Топ-пилоты трактуют трейсы как секрет.

**Что выживает (узко):** distance-axis TIME/pedal эталон (`speed/throttle/brake/g` по `s=Σv`, выравнивается к
нашей normalized-позиции) из круга, которым пользователь **владеет лично** (свой `.ld` = своя скорость, не
beyond-PB; купленный CDA-пак = beyond-PB, но платно/локально/без линии/без бандла). Сильно пересекается с уже
существующим PB-TIME коучингом — добавляет лишь ВНЕШНИЙ более быстрый якорь, и только если юзер сам его купил.

**Сквозной вывод A/B/MoTeC:** grid-anchored **beyond-PB LINE** требует МИРОВЫХ координат, а они есть только в
**живом** SHM. Отсюда реальные оставшиеся направления beyond-PB-линии: **(B′) живой захват линии соперника**
(гонка vs сильный AI → его `carCoordinates` из графической страницы live) и **(C) синтетическая оптимальная
линия из границ трассы**. Плюс всегда-безопасный **relative-коучинг** (measured g vs PB, без абсолютов/линии).

*Firsthand-проверка (реальный `monza-bmw_m4_gt3` `.ld`, спека-derived парсер `ld_probe.py`, не GPL):*
- *T1 ✅ ПОДТВЕРЖДЁН — 55 каналов декодятся с верными единицами/диапазонами (SPEED/THROTTLE/BRAKE/STEER/*
  *GEAR/G_LAT/G_LON/ROTY-yaw/RPM/WHEEL_SPEED×4/TIME).*
- *T2b ✅ ПОДТВЕРЖДЁНО что мировых координат НЕТ — ноль каналов pos/coord/dist/spline; дистанция только `Σv·dt`.*
- *Доп. трение: у скачанного файла `.ldx` пустой (`<MarkerGroup Name="Beacons"></MarkerGroup>`) и `LAP_BEACON`=0 —*
  *лап-границ нет, а без канала дистанции/позиции чужой `.ld` нечем разбить на выровненные круги.*
